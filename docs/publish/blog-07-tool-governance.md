# 技术博客⑦：把工具层收成「可治理」——schema、降级、评测集与一次故障注入

> 系列第七篇。这篇讲我最近一轮整改：**工具治理（P1-2）+ 显式规划（P1-3）+ 20 条 Agent 评测集（P1-1）**。
> 核心问题只有一个：**"能跑"的 Agent 和"敢交付"的 Agent 差在哪？**

## 开头：一次真实的失败回放

先讲个真事。我在跑评测集时故意把 arXiv 接口"弄挂"（故障注入，后面讲怎么弄的），
任务要求引用 arXiv 论文。结果：

- 报告照常产出（5,545 字），质检 passed；
- Agent 自动改用知识库里的 arXiv 论文存档 + PubMed + GitHub 开源项目完成检索；
- 轨迹里完整记录了「arXiv 暂不可用：故障注入……可改用 search_knowledge / query_filings」。

**单源故障不炸整单**——这是"敢交付"的第一条。

## 1. 工具层为什么需要"治理"

整改前，工具长这样：散落在编排器里，外部 API 各写各的（arXiv 睡 3 秒、S2 自己写退避、
PubMed 裸奔），MCP 是一个 `mcp_call(工具名, JSON字符串)` 调度器——模型要先背工具名再拼
JSON，参数错了也没人告诉它哪错了。

整改后（`agent/tools.py`）：

1. **每个工具一份 schema 元信息**：必填字段、取值范围（如 limit 1~10）、超时、来源、降级策略；
2. **参数校验失败回给模型"哪错了"**：`limit=99` → 返回"参数错误：limit 需在 1~10 之间"，
   模型读到后自己换工具——异常不抛到编排器外面；
3. **外部 API 统一收口**（`external_get`）：连接类错误**立即降级不重试**（单源故障不拖死任务），
   429/5xx 指数退避最多 3 次，全部失败返回带替代工具提示的降级文案；
4. **MCP 拆成独立 Tool**：每个 MCP 工具映射成一个独立 smolagents Tool，
   schema 直接来自 MCP 的 inputSchema，模型不用再背工具名。

配套加了一个**故障注入钩子** `SIMULATED_API_FAILURES=arxiv`——命中 URL 即模拟失败。
这玩意儿不是测试造假，是企业化验收手段：**"你说能降级，演示给我看"**。

## 2. 先规划，后执行（P1-3）

Researcher 动笔前，先注入一份规则模板规划（零成本、确定性、可评测）：

```
大纲（4 节）：概述 → 公司分析 → 财务表现 → 风险与展望
1.「概述」：search_knowledge（知识库全文）
2.「财务表现」：优先 query_filings（SEC 财报披露），再补新闻语境
两条硬约束：
1. 精确财务数字必须来自 SEC 语料并附来源链接
2. 禁止出现无来源的精确数字
```

规划随轨迹落盘，质检要求问题注明所属小节。这让"数字纪律"从口头约定变成任务的一部分。

## 3. 20 条任务集：把"我觉得还行"变成数字

任务集（`eval/tasks.json`）每条固定：选题、必用工具、禁止的幻觉模式、3~5 条可核对事实。
指标只留企业听得懂的 4 个：**成功率 / 无引用数字率 / 步数 / 成本**。

首轮实测 24 条（23 条完成、1 条触发预算熔断；含研投基本面 4 条）：

| 指标 | 值 |
|---|---|
| 任务成功率 | 0.652（15/23 质检通过） |
| 无引用数字率（均值） | 0.577 |
| 平均步骤数 / 工具调用 | 88.1 / 145.8 |
| 平均耗时 / 预算 | 314s / 189 万字符 |

几个诚实的发现：

- **t14（LLM Agent 硬件设计自动化调研）撞了预算熔断**：4M 字符预算用尽被熔断。
  这不是 bug，是预算熔断器在工作——但说明学术调研任务的信息密度低、token 消耗大，
  这类任务需要更聚焦的检索策略；
- **7 条任务质检未过**，主要死因是"无来源精确数字"——模型总想给出精确数字，
  这正是无引用数字率指标存在的意义；
- **2 条任务漏用了必用工具**：模型绕过了 search_graph 用知识库硬答。工具暴露 ≠ 工具被用，
  这是后续要优化的点（更明确的规划约束）；
- **研投 4 条（t21~t24）2 条质检通过**：合规检查（无投资建议/免责声明）全部命中，
  财务数字均能回溯到 SEC 来源。

评测的意义不是"我 100 分"，而是**把失败变成可归因的清单**——每条失败都能指到
轨迹里的具体步骤。

## 4. 顺带补的：研投基本面分析

用户场景里"基本面分析"需求最实在，加了 `basic_research` 报告类型：

- 章节：公司概况 / 业务结构 / 财务表现（营收、毛利率、净利率、现金流）/ 资产负债表 / 竞争力 / 风险展望；
- **合规边界写进模板**：禁止目标价、估值结论、买卖建议；财务数字强制 SEC 来源；
  报告自动追加"不构成投资建议"免责声明；
- 评测集新增 t21~t24 四条财务任务，checkpoint 含"不得出现投资建议"。

## 结语：企业看的是"失败怎么收"

这轮整改最大的认知：**企业不问你 Agent 多聪明，问的是挂了怎么收**。
工具降级、预算熔断、轨迹回放、可归因的评测集——这些"不性感"的工程，
才是"敢交付"的底气。
