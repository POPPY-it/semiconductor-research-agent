# 技术博客⑤：企业级加固——一个 Agent 产品上线前的安全与可靠性清单

> 系列第五篇。前四篇把产品从内核做到了上线，这一篇聊一个更"无聊"但更值钱的话题：
> **把 demo 变成生产系统，靠的不是加功能，而是补"不出事"的能力。**
> 我把上线前必须过的一道道关，连同踩过的坑，整理成一份清单。

## 1. 安全：先堵住最愚蠢的洞

**SSE 的 token 泄露。** 我最初用 `?token=xxx` 给 EventSource 传鉴权，因为 EventSource 不能自定义 Header。这个 token 会出现在：访问日志、浏览器历史、反向代理日志。对个人 demo 无所谓，对企业系统就是安全事故。

修法：**登录换 HttpOnly Cookie**。`POST /auth/login` 用 X-API-Token 校验，通过后签一个 HMAC 签名的 Cookie（带过期时间），EventSource 同源自动携带。token 从 URL 里彻底消失。

配套：**速率限制**（建任务 5 次/分钟、登录 10 次/分钟）、**请求审计**（X-Request-ID + 结构化访问日志）。这三样加起来，才敢说"能对公网开放"。

## 2. 可靠性：进程挂了、任务丢了怎么办

三个问题，三个答案：

1. **进程重启后，排队中的任务卡死在 running？** → 启动时扫描并把 `queued/running` 的会话标记为 error，前端给"重试"按钮。数据完整性优先于"看起来还在跑"。
2. **质检不通过，报告还发吗？** → 做成可配置策略：`caveat`（注入警示横幅交付）或 `reject`（拒绝交付正文）。默认 caveat——对研究类内容，隐瞒风险比交付带风险提示更糟。
3. **并发写 SQLite 事务冲突**（"cannot start a transaction within a transaction"）→ 单连接 + 锁 + 自动提交模式。这个 bug 是我的限流测试用并发场景逼出来的——**没有并发测试，你永远不知道自己的代码是单线程安全的**。

## 3. 成本治理：给 LLM 上保险丝

我亲眼看着修订循环单轮累计 52 万 input tokens。对公开产品，一次"深度研报"能烧掉几块钱，还没人给你报销。

方案：**token 预算熔断**。包装 Model，累计估算字符数，超预算直接抛异常终止任务。上线的第一版我把预算定在 120 万字符，结果真实任务跑了 115 万——**差一点就误杀**。教训：熔断阈值必须用生产数据校准，否则它保护的不是成本，是用户体验。

配套：**备用 LLM**。主模型连接/超时/限流类错误，自动切换一次备用模型，结果里记录 model_used。单点依赖是生产系统最忌讳的。

## 4. 可观测：出事时你能看到什么

- **指标**：Prometheus 文本格式（HTTP 请求数/4xx/5xx/429、任务总数按状态、任务耗时）
- **健康检查**：不只返回 "ok"，而是队列深度、文章数、QA 策略、当前/备用模型
- **CI 三流水线**：pytest（37 个测试）+ 前端构建 + Docker 镜像构建——每次 push 自动验证

## 5. 三条真实踩坑（比功能更值钱）

1. **BudgetedModel 不兼容 ChatMessage 对象**：smolagents 传的是对象不是 dict，我的估算代码用 `.get()` 直接炸。兼容对象和 dict 两种形态。
2. **熔断错误被包装得看不懂**：smolagents 把 `BudgetExceededError` 包成 `AgentGenerationError`，用户看到的是"Error in generating model output"——沿异常链解包，把人类可读的原因抛给前端。
3. **并发 bug 靠测试逼出来**：限流测试让 5 个任务真并发，SQLite 立刻现形。**没有并发测试，就没有资格谈生产。**

## 结论

"企业级"不是一个状态，是一份清单：安全、可靠性、成本、可观测，每一项都有测试兜底。这份清单的价值在于——面试官问"你这个和 demo 有什么区别"时，你能一项项指着说。
